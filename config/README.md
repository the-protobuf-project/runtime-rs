# tpp-config

Layered application configuration over [Figment](https://docs.rs/figment):
defaults compiled into the binary, a development profile, configuration files
in TOML, YAML or JSON, and environment variables, read into your own typed
sections. It loads configuration the way a Go service generated by
`protoc-gen-service` (`app=<name>`) does, so a Rust and a Go service of one
system are configured alike: the same files, the same variables.

## Install

```bash
cargo add tpp-config
cargo add serde --features derive
```

The library is imported as `config`.

## Load, then read typed sections

```rust
use serde::Deserialize;

#[derive(Deserialize)]
struct Server {
    host: String,
    port: u16,
    #[serde(default, deserialize_with = "config::de::comma_list")]
    allowed_origins: Vec<String>,
}

fn main() -> Result<(), config::Error> {
    let config = config::Loader::new("acme")
        // The defaults, compiled in: the binary runs with nothing beside it.
        .release(config::Source::toml(include_str!("acme.release.toml")))
        .dev_profile(config::Source::toml(include_str!("acme.dev.toml")))
        // Any file, its format named by its extension.
        .discover(["acme.toml", "acme.yaml", "acme.json", ".config/acme.toml"])
        .load()?;

    let server: Server = config.section("server")?;
    println!("listening on {}:{}", server.host, server.port);
    Ok(())
}
```

## Precedence

Each layer overrides the ones before it, key by key; the environment
overrides everything.

| Order | Layer | Set with |
| --- | --- | --- |
| 1 (lowest) | The application's defaults, embedded | `Loader::release(Source::toml(include_str!(..)))` |
| 2 | The development profile: `acme.dev.toml` in the working directory when there, else the embedded profile with `ACME_PROFILE=dev`; none with `ACME_PROFILE=release` | `Loader::dev_profile`, `Loader::dev` |
| 3 | Configuration files: added ones, the first discovered, then the one `ACME_CONFIG` names | `Loader::file`, `Loader::discover`, `ACME_CONFIG=/etc/acme/prod.yaml` |
| 4 | Providers of your own (a secret store, a remote config service) | `Loader::provider` |
| 5 (highest) | Environment variables | `ACME_SERVER__GRPC__PORT=50051` |

## Formats

| Format | Extensions | Embedded | From a file |
| --- | --- | --- | --- |
| TOML | `.toml` | `Source::toml` | `Source::file("acme.toml")` |
| YAML | `.yaml`, `.yml` | `Source::yaml` | `Source::file("acme.yaml")` |
| JSON | `.json` | `Source::json` | `Source::file("acme.json")` |

`Source::file` fails the load when the file is missing; `Source::optional_file`
skips it. A file is read where its path points, relative to the working
directory. Any other extension is refused with `Error::UnsupportedFormat`.

## Environment variables

The prefix is the application's name upper-cased: `acme` reads `ACME_*`. The
rest of a name is the key, with double underscores between levels, so a key
keeps its own underscores:

| Variable | Key |
| --- | --- |
| `ACME_SERVER__GRPC__PORT=50051` | `server.grpc.port` |
| `ACME_WEBHOOKS__SECRET_KEY=...` | `webhooks.secret_key` |
| `ACME_SERVER_PORT=50051` (no double underscore) | `server.port` |

Values are typed as the section reads them: `true` is a bool, `50051` a number.
A list is one comma-separated string; read it with `config::de::comma_list`.
`ACME_PROFILE` and `ACME_CONFIG` steer the load and are not keys.

## Reading

| Call | Returns |
| --- | --- |
| `config.extract::<App>()` | The whole configuration |
| `config.section::<T>("search.opensearch")` | One section, by dotted key |
| `config.section_or_default::<T>(key)` | The section, or `T::default()` when nothing sets it |
| `config.extract_validated` / `section_validated` | The same, then `Validate::validate`: refused at startup, naming the key |
| `config.contains(key)`, `profile()`, `is_dev()`, `files()` | What the load found |
| `config.figment()` | The merged layers, e.g. for `find_metadata` (which layer set a value) |

`config::global::install(config)` keeps one configuration for the process;
`config::global::get()` reads it anywhere.
